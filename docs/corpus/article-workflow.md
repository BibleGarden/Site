решение отдельным ADR в Architecture/decisions/.

## 1. Бриф на русском

Взять одну тему из [плана, раздел 3](../seo/lampada-semantic-core-and-content-plan.md#3-контент-план).
Порядок P1 → P2 → P3, одна статья до мержа, затем следующая; #7 — последняя
из P1. Перед началом проверить актуальность постановки и состояние корпуса.

Заполнить [шаблон исследователя](prompts/research.md): номер/приоритет/slug,
читатель и его вопрос, запросы en/ru/uk, угол, обещанная практическая польза,
предварительная структура, границы темы и соседние статьи. Для темы 1:
трёхминутный пример молитвы и пять вопросов; собственные слова дополняют
молитвенное правило, а не объявляют его ненужным. Это рамка исследования,
а не разрешение заранее приписать такую позицию любому автору.

Сохранять все правила раздела 3.1 плана: прямой ответ в начале, полезный
сохраняемый материал, FAQ по делу, таблица при содержательном сравнении,
подпись «Команда Lampada», источники и рецензент там, где нужен. Не приписывать
команде книжный опыт. До релиза CTA — «Скоро в App Store», без обещания
доступной установки. Все три языка под одним slug, локализация под свой интент.

## 2. Поиск и чтение

1. Сверить [реестр](lampada-books.md), законность копии и актуальный `GET /books`.
   «В корпусе» в реестре означает отбор, а не доказанную индексацию. Зафиксировать
   дату и способ проверки, недоступные книги и пробелы покрытия.
2. Составить несколько запросов на ru и en: бытовая проблема, понятия,
   личный опыт, возражения. Добавить языки доступных книг (например fr).
   Отдельные точные фильтры `book_id`, `author`, `tradition`, `language`, `license`
   соединяются AND. **Всегда выполнить также запросы без фильтров**: language —
   только дополнительный проход, иначе неверные метаданные скроют книги.
   Проверить фактический язык текста каждого hit; API может хранить язык
   оригинала вместо языка издания. Подозрительные language/translator записать
   в досье как проблему для владельца корпуса, не исправлять в Site.
   У переводного издания должен быть назван переводчик (ADR-0018): при null
   цитирование запрещено до исправления. Пересказ возможен с атрибуцией издания,
   если остальные требования, включая главу и законность копии, выполнены.
   Не ограничивать всё исследование одной традицией или первыми hits.
3. Запустить помощник ниже. Score — релевантность запросу, не достоверность.
   Не включать нерелевантный фрагмент ради числа источников.
4. Для каждого серьёзного кандидата запросить
   `POST /api/v1/channels/lampada/search/context` с
   `{"chunk_id":"<id>","scope":"chapter","before":3000,"after":3000}`.
   Scope задаёт границу, но не гарантирует выдачу всей главы: читать
   соседние диапазоны в пределах `section_char_start/end`, пока не понятны
   история, адресат и вывод. **Если chapter равен названию книги либо границы
   раздела охватывают всю книгу — стоп для этого источника.** Записать book_id,
   chunk_id, chapter и границы, сообщить владельцу корпуса. Правило «книга +
   глава» не выполнено: не извлекать главу из section_path вручную и не обходить
   проблему через leaf/полный текст. После исправления корпуса проверить заново.
   Контекст хранить только вне git.
5. Предисловие/текст без глав может дать 422: записать это и явно запросить
   `scope=leaf` только для ознакомления. Если реальная глава не установлена,
   источник остаётся заблокирован для статьи; leaf не заменяет главу.
   HTTP 409/ошибки API останавливают запуск; не ретраить автоматически и не
   подменять книгу. Уточнить состояние индексации и явно обновить исследование.
6. Выбрать фрагменты минимум из **трёх разных книг трёх разных авторов**,
   желательно разных традиций. Искать места, где пережитый опыт переходит
   в размышление и вывод; отличать свидетельство автора от пересказанной им
   истории другого человека. Проверить реестровые пометки «спорное: …»:
   оговорку назвать в тексте, не предлагать спорный опыт как образец. Роман
   (например Бернанос, Гюисманс) — художественный сюжет, не прожитый опыт автора.
   Не представлять разногласия как общий консенсус. Русские служебные названия
   традиций из API преобразовать в понятные читателю и локализовать для en/uk;
   сами метаданные corpus_sources копировать точно.

## 3. Досье и решение Марии

Помощник создаёт список кандидатов с запросами, метаданными, главой/разделом,
короткой выдержкой, `chunk_id`, диапазоном чанка и `text_sha256`. Он не читает
главы, не выбирает окончательные цитаты и не гарантирует три независимых голоса.
Исследователь дописывает:

- бриф, зачем каждый выбранный фрагмент, что в нём опыт, а что вывод;
- результат чтения контекста, ограничения, противоречия и отвергнутые кандидаты;
- какие утверждения и разделы будущего текста поддержит каждый источник;
- пробелы корпуса, вопросы Марии, статус согласования.

В git остаются только краткие, необходимые для выбора выдержки и собственные
аналитические заметки. Не коммитить главы, полные chunks, книги, приватные
отчёты checker или секреты; папка docs не даёт разрешения распространять корпус.
Это следует [ADR-0018](https://github.com/BibleGarden/Architecture/blob/main/decisions/0018-book-corpus-legal-basis.md).
Длина выдержек определяется целью, не «безопасным процентом».

**Стоп перед текстом:** Мария утверждает досье (бриф/угол, список chunk_id,
допустимые выводы и спорные места). Записать дату и ссылку на решение в досье.
Если не хватает трёх авторов или контекста — запросить решение, не выдумывать
недостающие источники. Новый источник/существенная смена угла возвращают досье
Марии. Исследовательский пример в этом PR такого одобрения не имеет.

## 4. Ru: текст, цитаты, проверка, ревью

Передать автору [шаблон](prompts/writer.md) и утверждённое досье. Каждое
утверждение о духовной жизни связать с фрагментом книги; от редакции — связки,
практические советы по приложению и явно обозначенные авторские скрипты молитвы.
Не превращать богословское утверждение в бездоказательный «практический совет».
Пересказ — наша лексика и структура; цитата — точный непрерывный фрагмент,
короткий настолько, насколько требует мысль. Традицию автора назвать рядом.

Файлы: `content/lampada/articles/<slug>/{ru,en,uk}.md`; образец формата —
`template-check` (технический черновик, не образец содержательной статьи).
Front matter: `title`, `description`, `date`, `draft: true`, затем
`corpus_sources` по [точной схеме](citations.md). Не добавлять произвольные поля
для традиции/автора: традиция пишется в тексте, подпись команды задаёт сайт.
Для цитат Писания назвать конкретный перевод и дать точную ссылку на него
(Синодальный, Кулаковых, BSB, WEB, Хоменка — по реально использованному тексту
и правам). Термины точны: рефлексия приложения — не examen, вопросы — не
духовное руководство. Тема #1 — хаб; планировать внутренние ссылки на связанные
темы, обязательно #1 ↔ #13. До появления опубликованной цели отметить связь
в брифе, не публиковать битую ссылку.

Для каждого цитирования или пересказа отдельный элемент и `[^corpus-id]`
сразу после буквального `text`. Узкий диапазон `[char_start,char_end)` —
Unicode code points канонической книги, не байты и не позиции в статье.
Сохранить hash, book/chunk ID и метаданные из API. Только после проверки
реальной главы контекст `scope=leaf` помогает уточнить диапазон. При chapter,
равном названию книги, или разделе на всю книгу — стоп и сообщение владельцу
корпуса; не писать фиктивную главу в corpus_sources. Цитата без перевода:
`original` дословный, `translation: null`; наш перевод: `translation: ours`,
`original` остаётся дословным на языке индексированного издания. Пересказ:
`kind: retelling`, `original: null`, `translation: null`.
Переводчик исходного издания не равен автору нашего перевода. Правила Predanie.ru
и другие условия источника соблюдать; готовые тексты молитв/молитвословов
из плана публиковать только при допустимых правах, современные не копировать.
Краткие аналитические книжные цитаты регулируются ADR-0018 и citations.md.

```bash
python tools/check_corpus_citations.py content/lampada/articles/<slug>/ru.md \
  --report /tmp/lampada-ru-review.md
```

Exit 0 обязателен. Ошибка/неодобрение judge — исправить источник или текст,
заново проверить изменённый результат; отсутствие проверки не обходить.
Checker проверяет **только объявленные** источники. Рецензент Claude Opus
использует [чеклист](prompts/reviewer.md), ищет неразмеченные утверждения,
смысловые и правовые проблемы. После исправлений повторить затронутые проверки.
**Мария согласует ru на превью**; без этого локализацию не начинать.

## 5. En/uk, итоговая вычитка и мерж

Локализовать утверждённый смысл, примеры и запросы, не переводить ru механически.
Если ru-цитата была нашим переводом, en/uk переводить заново из того же
`original`, а не из ru. Для той же цитаты `original`, `book_id`, `chunk_id`,
hash и диапазон остаются прежними; меняется `text`. Если язык целевой версии
совпадает с источником — взять дословный `original` и `translation: null`.
Новая цитата/издание требует нового источника и проверки; не менять original,
чтобы он лучше совпал с локализованным текстом. Локализованный пересказ также
проверяется заново. Все переводы сверить с корпусом; ревью en/uk — Claude Opus.

```bash
python tools/check_corpus_citations.py content/lampada/articles/<slug>/{ru,en,uk}.md \
  --report /tmp/lampada-all-review.md
python -m sitegen build
python -m sitegen check
python -m unittest discover -s tests
```

**Мария вычитывает все три версии и разрешает мерж**. Богословские вопросы и
тексты молитв передать рецензенту соответствующей традиции. Снять draft только
после принятия; пересобрать и закоммитить публичный dist вместе с Markdown.
PR содержит тему, ссылки на задачу/досье/решения, проверки и оставшиеся риски,
но не приватные тексты отчётов. Перед push — rebase от свежего origin/main,
CI без ошибок. Мерж не означает разрешение на деплой: задача 8 отдельная.

## Запуск помощника

Зависимости помощника — стандартная библиотека Python 3. Ключ читать в runtime
из приватного окружения, как описано в [citations.md](citations.md):
`CORPUS_API_KEY` получает `API_KEY` channel-ai; не передавать ключ аргументом.
`CORPUS_API_URL` по умолчанию `http://127.0.0.1:3018`. Не коммитить `.env`.

```bash
python tools/corpus_research.py \
  --queries docs/corpus/dossiers/01-prayer-own-words.queries.json \
  --topic 'Как молиться своими словами: с чего начать' \
  --output /tmp/01-prayer-own-words-candidates.md
python -m unittest discover -s tests -p test_corpus_research.py
```

Queries — непустой JSON-массив точных search payload. Фильтры берутся из API;
в примере book_id относятся к снимку этого корпуса. Лимиты по умолчанию:
два hits на книгу, 12 всего, выдержка до 180 символов (максимум 300).
Выдержка выбирается из предложения с наибольшим буквальным совпадением
слов запроса (первые четыре буквы, без частых служебных слов); API не даёт позицию
семантического совпадения внутри чанка. При отсутствии буквального совпадения
это явно указано вместо произвольной выдержки. Агент читает контекст и выбирает
смысловой фрагмент сам. Длинное предложение ограничивается окном вокруг
совпадения; для цитирования нужно заново выбрать точный диапазон.
Существующий output не перезаписывается: используйте новое имя; `--force` —
явное разрешение заменить файл после переноса нужных редакторских заметок.
`--query-delay 5` задаёт явную паузу между запросами (по умолчанию 0, максимум
30 секунд), без повторов ошибочных запросов.
Дедупликация по `(book_id, section_index)` оставляет лучший score, объединяет
номера запросов. Увеличивать покрытие осознанно; короткие выдержки не заменяют
чтения контекста. Пустой поиск целиком, неверный ответ/ключ/API завершают запуск
с ошибкой без записи досье. Частично пустые запросы видны по числу hits.
