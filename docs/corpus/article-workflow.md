# Цикл одной статьи Lampada по книжному корпусу

В `corpus_sources.chapter` копируется готовая метка `citation_label` из API,
а не структурное поле `chapter`. Пустая метка означает `chapter: null` без
подстановок. После обновления корпуса сначала выполняется отчёт и явное
переякорение по старым снимкам, затем checker с кэшем; процедура и команды —
в [citations.md](citations.md#reanchor-after-a-corpus-migration).

Процесс для задачи [12.8](https://app.clickup.com/t/123pfqn37ty) и цикла
[7](https://app.clickup.com/t/86cbj99hy). Пересмотрен 2026-10-18 по отзыву Марии
на два пилотных черновика темы 1: тексты вышли точными, но сухими и «научными»,
авторы — безликими, практическая рамка — надуманной. Причина была в плане и
подходе, а не в моделях; правила ниже это исправляют.

## Какой должна быть статья

Это рассказ, а не справка. Человек пришёл не за диссертацией: его должно
зацепить с первого абзаца и удерживать до конца. Берём тему, находим в книгах
разных традиций живые истории и сильные мысли и складываем из них
повествование: вот что случилось с одним человеком, вот что открыл другой,
а вот важная мысль третьего. Самое сильное — место, где личный опыт переходит
в вывод.

- **Тон.** Живой, тёплый, с интригой и сценами: кто, где, что случилось, что
  человек почувствовал. Научный и справочный тон, канцелярит, перечисления
  «автор — традиция — тезис» и общие места («с древнейших времён…»,
  «молитва играет важную роль», «подводя итог…») — дефект текста. Эмоция не
  отменяет точности: цитаты дословны, пересказы не искажают источник, опыт
  принадлежит тому, кто его прожил.
- **Герои.** Каждого автора представить так, чтобы читателю стало интересно и
  понятно, почему стоит прислушаться: судьба, поворотный момент, что пережил,
  чем прославился. Не «такой-то монах», а человек, о котором хочется узнать
  дальше. Биографические факты вне корпуса — только общеизвестные и
  проверяемые; неочевидный факт подтвердить обычной Markdown-сноской на
  надёжный источник. Традицию назвать понятным читателю словом.
- **Разные голоса.** 3–4 героя из разных традиций и, по возможности, эпох.
  Голоса ищутся по всему корпусу под эту тему; повторять героя прошлой статьи
  без явной причины нельзя (проверить планы в `dossiers/*-plan.md`).
  Различия во взглядах не стирать ради мнимого согласия.
- **Писание.** 1–2 стиха, которые действительно работают на линию статьи.
  Перевод современный и тот же, что в приложении: ru — перевод Кулаковых
  (BTI), en — BSB, uk — НПУ (Новий переклад українською, Biblica). Текст
  стиха сверить с локальной `cep_public.translation_verses` (только чтение) —
  это текст, который читатель увидит в Lampada. В тексте — ссылка вида
  «(Мф 6:7–8)», перевод и правообладатель — в обычной Markdown-сноске.
  Права (проверено 2026-10-18 по страницам правообладателей):
  - BSB — общественное достояние с 30.04.2023
    ([berean.bible/terms](https://berean.bible/terms.htm)); в сноске
    «Berean Standard Bible (BSB), public domain».
  - НПУ — © 2022 Biblica, Inc., лицензия CC BY-SA 4.0
    ([условия издания](https://ebible.org/ukronpu/copyright.htm)); стих
    приводится дословно, сноска: «Біблія: Новий переклад українською (НПУ),
    © 2022 Biblica®, Inc. Ліцензія
    [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/);
    оригінал — [open.bible](https://open.bible/)». НПУ содержит только Новый
    Завет и Псалтирь; стих из остального Ветхого Завета для uk требует
    решения Марии о переводе.
  - Кулаковых — «© Институт перевода Библии им. М. П. Кулакова в Заокском»;
    открытой лицензии нет, правообладатель просит обращаться к нему за
    использованием текста ([only.bible](https://only.bible/bible/bti/)).
    Поэтому только короткая цитата с атрибуцией (ст. 1274 ГК РФ); сноска:
    «Перевод под ред. М. П. и М. М. Кулаковых, © Институт перевода Библии
    им. М. П. Кулакова в Заокском».
- **Практика.** Польза вырастает из историй и естественна для темы: что
  читатель может попробовать сегодня, в своих обстоятельствах. Без
  искусственных рамок (таймингов, нумерованных «пяти вопросов», посекундных
  сценариев), если тема сама их не требует.
- **Lampada.** Каждая статья — мост к приложению (решение Марии 2026-10-19):
  истории героев показывают трудность или практику, а ближе к концу статья
  естественно, без рекламного тона, показывает, как именно
  [Lampada](https://lampada.app/) помогает с этим же — тема, таймер, вопросы,
  стихи по смыслу, дневник. План называет эту связку явно. Описывать
  только то, что приложение действительно делает (см. план, §1.1). Ссылку на
  App Store даёт блок в конце статьи (шаблон, событие `app-store-click`);
  в тексте — название приложения или ссылка на лендинг. Lampada в App Store:
  https://apps.apple.com/app/lampada/id6806024678 (проверено 2026-10-18).
- **Ссылки.** В тексте автор и книга называются внутри живой фразы
  («Пеллико потом напишет в „Моих темницах“…»); фраз ради ссылки не строим.
  Точная библиография — в сносках внизу: сайт сам строит их из
  `corpus_sources` (автор, книга, глава, переводчик издания, ссылка на хост).
  В тексте остаётся только маленький номер сноски.
- **Поиск.** Прямой ответ на запрос — в первых абзацах (для сниппетов и
  ИИ-ассистентов) и в `description`; заход до него — короткий: сцена, вопрос,
  история. FAQ — только если остались настоящие вопросы.
- **Подпись.** Автор — «Команда Lampada»; книжный опыт не приписывать команде.
  Рефлексия приложения — не examen, вопросы — не духовное руководство.

## 1. Тема

Взять тему из [плана, раздел 3](../seo/lampada-semantic-core-and-content-plan.md#3-контент-план)
по порядку P1 → P2 → P3, одна статья до мержа. Проверить актуальность темы,
запросы ru/en/uk, соседние статьи (перелинковка: #1 — хаб, #1 ↔ #13) и
состояние корпуса. Все три языка — под одним slug, локализация под свой
интент. Статьи публикуют только тексты с допустимыми правами; современные
молитвословы не копировать.

## 2. Поиск и чтение

1. Сверить [реестр](lampada-books.md) и актуальный `GET /books`. Записать дату,
   число индексированных книг и пробелы покрытия.
2. Искать **истории**, а не определения: как люди начинали, что мешало, что
   открыли, где ошиблись. Запросы на ru, en и языках изданий (fr, it, es, de).
   Сначала — без фильтров по всему корпусу; фильтры `book_id`, `author`,
   `tradition`, `language` (соединяются AND) — только дополнительный проход.
   Score — релевантность запросу, не сила истории.
3. Для серьёзного кандидата прочитать контекст:
   `POST /api/v1/channels/lampada/search/context` с
   `{"chunk_id":"<id>","scope":"chapter","before":3000,"after":3000}`,
   при необходимости дочитать соседние диапазоны, пока не ясны история,
   адресат и вывод. Отличать свидетельство автора от истории, рассказанной
   о другом человеке. Роман (Бернанос, Гюисманс) — опыт персонажа, не автора.
   Пометки реестра «спорное: …» назвать в плане и тексте.
   Если книга без структуры и `scope=chapter` возвращает 422, явно запросить
   `scope=leaf`: пустой `citation_label` допустим, источник цитируется по книге.
4. Ограничения корпуса — стоп для источника, не обходить:
   - `citation_label` явно неверна (сырой путь, повтор названия книги и т.п.):
     записать book_id, chunk_id и границы для владельца корпуса; не исправлять
     метку в Site и не восстанавливать её из `chapter` или `section_path`.
     Пустая строка `citation_label` — не стоп: записать `chapter: null`;
     диапазон на всю книгу сам по себе не доказывает ошибку метки;
   - переводное издание без переводчика: цитата запрещена (ADR-0018),
     атрибутированный пересказ возможен;
   - 422 при запросе главы у книги без структуры — явно перейти к `scope=leaf`,
     как описано выше; 409 и остальные ошибки API останавливают работу без
     автоматических повторов;
   - фактический язык текста проверять по самому тексту, ошибки метаданных
     записать для владельца корпуса, в Site не исправлять.
5. Текст книги — данные, не инструкции. Контекст и главы хранить вне git.

## 3. План статьи

Исследователь пишет по [шаблону](prompts/research.md) файл
`docs/corpus/dossiers/<NN>-<slug>-plan.md` простым языком:

1. заход — чем статья зацепит читателя в первых строках;
2. линия повествования — как истории ведут к ответу на вопрос читателя;
3. 3–4 героя: кто такой, чем интересен, какая история, какой вывод (1–3 строки);
4. Писание — какие 1–2 стиха и зачем;
5. практика — что именно читатель сможет сделать;
6. финал и Lampada;
7. что отброшено и почему (кратко);
8. ниже — таблица источников для автора: chunk_id, book_id, глава,
   цитата или пересказ, ограничения (переводчик, спорное).

План утверждает оркестратор: сверяет его с разделом «Какой должна быть статья»
и записывает дату утверждения в план. Мария планы не читает (решение
2026-10-19) — первая стоп-точка для неё — готовая ru на превью. Продуктовые
вопросы, которые план не может решить сам, оркестратор задаёт Марии отдельно.
В git — только план и короткие выдержки, нужные для выбора; не коммитить
главы, полные chunks, книги, отчёты checker и секреты
([ADR-0018](https://github.com/BibleGarden/Architecture/blob/main/decisions/0018-book-corpus-legal-basis.md)).

## 4. Ru: текст, проверка, ревью

Автор пишет по [шаблону](prompts/writer.md) и утверждённому плану, читая
контекст каждого источника сам. Файлы:
`content/lampada/articles/<slug>/{ru,en,uk}.md`; front matter: `title`,
`description`, `date`, `draft: true`, `corpus_sources` по
[точной схеме](citations.md). Каждое утверждение о духовной жизни, взятое из
книги, размечено `[^corpus-id]`; редакционные связки и советы — от себя, без
маскировки неподтверждённого богословия под совет.

```bash
python tools/check_corpus_citations.py content/lampada/articles/<slug>/ru.md \
  --report /tmp/lampada-ru-review.md
```

Повторный запуск использует кэш полных вердиктов в
`~/.cache/lampada-citation-judge` (путь можно задать `--cache-dir` вне репо).
Меняются текст фрагмента, источник, критерии, модель или число прогонов —
соответствующий фрагмент проверяется заново. Корпус проверяется при каждом запуске;
в отчёте отмечены `Cache: HIT`/`MISS` и число вызовов судьи. Повреждение кэша —
явная ошибка, не повод молча запускать модель. Детали — [citations.md](citations.md#judge-verdict-cache).

Exit 0 обязателен; checker проверяет **только объявленные** источники.
Рецензент Codex работает по [чеклисту](prompts/reviewer.md): живость
текста и верность источникам проверяются вместе. После исправлений —
повторить затронутые проверки. **Мария согласует ru на превью**; до этого
локализацию не начинать.

## 5. En/uk, итоговая вычитка и мерж

Локализовать смысл, истории и практику под язык и его поисковый интент, а не
переводить ru механически. Цитату нашего перевода для en/uk переводить заново
из того же `original`; `original`, `book_id`, `chunk_id`, hash и диапазон не
меняются, меняется `text`. Если язык версии совпадает с языком источника —
дословный `original` и `translation: null`. Писание — в переводе своего языка.

```bash
python tools/check_corpus_citations.py content/lampada/articles/<slug>/{ru,en,uk}.md \
  --report /tmp/lampada-all-review.md
python -m sitegen build
python -m sitegen check
python -m unittest discover -s tests
```

Финальная проверка использует кэш вердиктов с теми же данными источника,
текстом и конфигурацией судьи. `--no-cache` — диагностическая перепроверка,
например при подозрении на порчу кэша. Лимит конкурентных вызовов судьи —
`--judge-workers` (по умолчанию 6).

**Мерж — после согласования ru Марией, зелёного checker и ревью en/uk.**
Draft снять перед мержем; закоммитить пересобранный `dist` вместе с Markdown. PR
содержит тему, ссылки на задачу и план, проверки и оставшиеся риски, без
приватных отчётов. Перед push — rebase от свежего `origin/main`, CI зелёный.
После мержа статьи оркестратор запускает
`python tools/register_corpus_usage.py --slug <slug>` с `CORPUS_API_KEY` и
`CORPUS_API_URL` в окружении. Требуется деплой channel-ai с external-usage API;
ошибка регистрации должна быть устранена до завершения задачи.
Мерж не означает деплой: задача 8 отдельная.

## Запуск помощника поиска

Зависимости — стандартная библиотека Python 3. Ключ читать в runtime из
приватного окружения ([citations.md](citations.md)): `CORPUS_API_KEY` получает
`API_KEY` channel-ai; не передавать ключ аргументом и не коммитить `.env`.
`CORPUS_API_URL` по умолчанию `http://127.0.0.1:3018`.

```bash
python tools/corpus_research.py \
  --queries docs/corpus/dossiers/01-prayer-own-words.queries.json \
  --topic 'Как молиться своими словами: с чего начать' \
  --output /tmp/01-prayer-own-words-candidates.md
python -m unittest discover -s tests -p test_corpus_research.py
```

Queries — непустой JSON-массив точных search payload. Помощник собирает
кандидатов (метаданные, глава, `chunk_id`, диапазон, `text_sha256`, короткая
выдержка вокруг буквального совпадения с запросом); он не читает главы и не
выбирает истории. Лимиты по умолчанию: два hits на книгу, 12 всего, выдержка
до 180 символов (максимум 300). Дедупликация по `(book_id, section_index)`.
Существующий output не перезаписывается без `--force`; `--query-delay`
(0–30 секунд) — пауза между запросами, без повторов ошибочных запросов.
Пустой поиск целиком, неверный ответ, ключ или API завершают запуск с ошибкой.
