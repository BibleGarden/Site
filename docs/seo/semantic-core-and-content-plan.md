Задача: [Собрать семантическое ядро и контент-план bible.garden](https://app.clickup.com/t/86cbj99ht).
Статус: черновик на согласование (2026-09-20; ревизии: 2026-09-20 — ревью двух агентов; 2026-09-23 — все темы на трёх языках, колонка uk, #23 слита с #13, #17 и #26 локализованы, без деления на партии, автор «Команда Bible Garden», языковые кампании App Store; таблица 2.4 пересчитана скриптом). Очищенные выгрузки — в [`data/`](data/) (см. 1.2).

### 1.1 Что есть в приложении (проверено 2026-09-20 по `BibleGarden/iOS-App` и `cep_public`)

Статьи обещают только то, что есть; список ниже — граница честности.

- Платформа: **только iOS** (iPhone и iPad, iOS 15+, SwiftUI), опубликовано в [App Store](https://apps.apple.com/app/bible-garden/id6758955373). Android-версии нет — запросы «на андроид», `for android` не целевые; `for ipad` — целевые.
- Канон: 66 книг (протестантский состав) во всех переводах; второканонических книг нет. Покрытие аудио по `voice_alignments`: все дикторы — 66 книг, кроме Бондаренко (62 из 66) и НПУ (28: Новый Завет и Псалтирь).
- Права на записи: свободный текст не означает свободную запись. WEB — public domain по описанию; BSB (OpenBible), Бондаренко, Прудовский (Сретенский монастырь, 1989), Козлов, НПУ (Biblica/Davar) — статус для публикации фрагментов **на сайте** не подтверждён; до выяснения аудиопримеры на страницах — только WEB, остальное — через переход в приложение.
- Языки интерфейса и Библии: ru, en, uk. Активные переводы: en — BSB, WEBBE, WEBUS; ru — Синодальный (SYNO), перевод Кулаковых / ИПБ Заокский (BTI); uk — перевод Хоменка (UBH), Новий Переклад Українською (NPU; аудио — только Новый Завет и Псалмы).
- Дикторы (таблица `voices`): Синодальный — Александр Бондаренко (драматическое музыкальное сопровождение; не озвучены Паралипоменон и Песнь Песней) и Илья Прудовский (Сретенский монастырь, 1989, без музыки; звук дочищен ИИ); Кулаковых — Никита Семёнов-Прозоровский; Хоменка — Ігор Козлов (студийная запись 2005–2006, украинская; русского чтения Козлова в приложении нет); NPU — озвучка Biblica; BSB — Bob Souer и David; WEB — Winfred Henson, WEBBE — издание eBible.org.
- Classic Reading: одна дорожка, паузы «нет / N секунд / полная остановка» после каждого стиха, абзаца или раздела; скорость 0,6–2×; авто-переход к следующей главе; управление с экрана блокировки.
- Multi Reading: конвейер шагов «чтение (перевод + диктор)» и «пауза», стих за стихом (или абзац/глава) во всех добавленных переводах; библиотека шаблонов.
- Прогресс: по главам и книгам, общий процент; отметка вручную или автоматически (конец аудио, 90 % стихов, текст дочитан); учёт перемоток. **Встроенных планов чтения нет.**
- Слова Иисуса выделяются по `<span class='jesus'>`. На 24.09.2026 в опубликованных данных разметка есть у UBH; после публикации задачи 6.0.3 она появится у WEBUS, WEBBE, NPU и BTI там, где её даёт источник. SYNO и BSB запланированы отдельной задачей 6.0.5. Проверка: `cep_public.translation_verses.html` и прод-API.
- Чего нет: офлайн-режима (аудио стримится), собственного таймера сна (но штатный таймер iOS «Остановить воспроизведение» останавливает любое аудио — этого достаточно для честной страницы), поиска, закладок, заметок, толкований, детского контента, «стиха дня», виджетов, веб-версии. Темы под эти запросы не пишем (кроме отмеченных «мостов» и открытого решения в 3.6).

### 1.2 Проверяемость цифр

- `data/bible-garden-kp-{en,ru,uk}.tsv` — все фразы Keyword Planner с серединой диапазона; `data/bible-garden-wordstat-ru.tsv` — показы Wordstat по seed и их расширениям; правила корзин — `data/cluster_bible_garden.py` (`python3 cluster_bible_garden.py en|ru`; его вывод — таблица 2.4, сверено 2026-09-23).
- Суммы в 2.4 — порядок величины для сравнения кластеров, **не трафик и не обоснование числа страниц**: число страниц определяется числом различимых интентов (одна страница — один интент), суммы лишь ранжируют их.
- Формат выдачи снят из Германии; для en целевые страны — США/Великобритания, для ru — русскоязычные вне России тоже, для uk — Украина. После подключения Search Console оценки заменяются фактическими показами по странам.
- Там, где в выдаче только магазины и продукты (например, `parallel bible` — печатные книги), пользователь может искать продукт, а не статью: такие страницы строить как продуктовые (что получит, как выглядит, аудиопример, ссылка в стор), а не как эссе.

Порядок работы — по приоритету P1 → P2 → P3: каждая тема — подзадача 6.N задачи [6. Одна страница — один интент: близкие формулировки (`read the bible in a year`, `365 day bible plan`, `bible in one year schedule`) закрываются одной статьёй, иначе страницы каннибализируют друг друга. ## 3.1 Правила для всех статей

- **Ответ сначала**, дальше развёрнуто; таблицы там, где есть что сравнить; FAQ-блок — ради читателя и ассистентов, а не ради расширенного сниппета (Google почти не показывает FAQ-результаты; требование `FAQPage` в постановке 86cbj99hx стоит смягчить до «где уместно»). Для аудио-страниц — `AudioObject`; `llms.txt` — задача [86cbj99j2](https://app.clickup.com/t/86cbj99j2).
- **Польза сразу** (жирным в структурах): календарь, чек-лист для печати, калькулятор, аудиопример, сравнение дикторов.
- **Запрос «слушать» → дать прослушивание**: аудиопример на странице (пока — WEB) или глубокая ссылка в главу приложения; объясняющий текст без аудио такой запрос не закрывает.
- **«Мостовая» страница проходит, только если посетитель получает обещанное до предложения альтернативы** (сегодняшний отрывок, файл, текст KJV) — иначе это дорвей.
- **Точность**: перевод, диктор, покрытие книг, музыкальное сопровождение и статус прав указываются у каждой записи; Кулаковых и РБО — разные переводы; «бесплатно», «пробный доступ» и «подписка» в сравнениях не смешивать; канон — 66 книг.
- **Доверие**: автор — «Команда Bible Garden» (en: Bible Garden team, uk: Команда Bible Garden), подпись и JSON-LD `author` (`Organization`) ведут на страницу «Как мы пишем» (`/about/`): кто стоит за проектом, тексты готовятся с помощью ИИ и вычитываются и утверждаются Марией, источники и переводы цитат; рецензент для богословских тем — там, где нужен; источники и точные ссылки на переводы цитат в каждой статье; цитаты — из переводов приложения, а перевод, которого в приложении нет (KJV в #26), называется с пометкой «в приложении нет».
- **Языки**: каждая тема выходит на en, ru и uk под одним slug — это локализация, а не перевод: содержание и примеры свои для каждого языка (решение Марии, 2026-09-23). Без поискового спроса версия всё равно пишется — под ссылки, переключатель языка и ИИ-ассистентов, и может быть короче. hreflang связывает все три версии.

## 3.5 Граница с lampada.app и пилот «стихи по темам»

- bible.garden владеет: чтение, прослушивание, переводы, дикторы, планы, книги, **подборки стихов по темам**. lampada.app владеет: как молиться, дневник, lectio divina, молитва за других; из своих статей ссылается на подборки здесь, не публикует свои.
- Пилот подборок: 5 тем (тревога, страх, благодарность, утешение, прощение) — контекст отрывка, перевод с указанием, почему выбран, прослушивание; только после проверки выдачи и с лимитом, потому что это семейство с риском дорвеев. Семантику собрать отдельно.

## 3.6 Открытое решение: веб-чтение и «стих дня»

Самые большие кластеры ниши исключены как «нам нечего предложить в вебе»: `bible online` 10K–100K, `библия онлайн` 46 418, `verse of the day` 100K–1M, `bible verse` 1M–10M. При этом Bible-API отдаёт тексты и аудио всех переводов, то есть контент существует. Варианты:

1. Оставить сайт статейным (текущий план). Плюс: дёшево, без риска дублирования public-domain текста, который есть на сотнях сайтов. Минус: эти кластеры остаются у bible.by/BibleGateway.
2. Программные страницы глав с плеером и переключателем переводов (Multi Reading в вебе) + Universal Links в приложение; пилот — Псалтирь (150 страниц) или Новый Завет. Плюс: уникальное сочетание (параллельный текст + аудио + ссылка в главу приложения), прямой путь к установкам. Минус: это отдельный веб-продукт (динамика, кэш, права на аудио, поддержка), а текст сам по себе Google считает дублем.
3. «Стих дня» как страница — требует функции и редакции; без приложения-виджета это чужая сила (YouVersion).

Решение Марии (2026-09-20): вариант 1 сейчас; вариант 2 оценить после первых 10 статей по данным Search Console, с пилотом на Псалтири, если статьи дают установки; при переходе к варианту 2 — отдельный ADR в `Architecture/decisions/`.


## 4. Выводы

1. Самый свободный и точно «наш» кластер — двуязычное чтение (#3): в выдаче печатные книги и сторы, статей нет, спрос 1K–10K в en и ~1,5 тыс. в ru.
2. Кластеры «как начать» и «план на год» (#1, #2) — самые объёмные информационные темы с реалистичной конкуренцией (reddit и блоги в топе) и прямой привязкой к фичам Reading Progress.
3. Сравнение приложений (#4) — единственная коммерческая тема с приемлемой конкуренцией; статья должна быть честной, иначе не удержится.
4. Переводы (#5) — конкурентно, но без хаба остальные статьи некуда ссылать за «каким переводом читать».
5. «Евангелие дня», «библия онлайн/скачать», именные переводы — большие цифры, но чужой интент; не тратим.
6. Функционал приложения ограничивает темы: только iOS/iPad, без офлайна, без встроенных планов; зато дикторы (Бондаренко, Козлов) — готовый ru/uk-трафик, поэтому #17 — P1 на всех трёх языках, с дикторами своего языка.
7. «Мостовые» статьи (по решению Марии 2026-09-20): под крупные запросы с чужим интентом («евангелие дня», «скачать», KJV-аудио) пишем страницы, которые сначала честно дают то, за чем пришли, а потом показывают альтернативу в приложении. Их три (#24–#26); расширять этот тип только после проверки первых двух в Search Console — иначе это превращается в дорвеи.
8. Украинская семантика собрана (2.3): спрос сопоставим с русским по Google при меньшей конкуренции — из P1-тем uk-спрос подтверждён только для #1 и #2 (вне P1 — ещё #21 и #26); остальные uk-версии, в том числе #3, #4, #5 и #17, — локализация по правилу 3.1.
9. Открытый кластер: **подборки стихов по темам** (`bible verses for anxiety`, `scripture for anxiety` — по 10K–100K; `bible verses about prayer` 10K–100K). В этом плане его нет; по решению в плане lampada.app он относится к bible.garden (Lampada только ссылается). Пилот и граница описаны в 3.5.
10. Открытые вопросы (владелец — Мария): права на аудиофрагменты для сайта (1.1); смягчение требования `FAQPage` в 86cbj99hx (3.1). Веб-чтение — решено (3.6).
11. Всего по данным оправдано 27 тем (#23 слита с #13), каждая на трёх языках; страницы «под каждое ключевое слово» не делаем — это каннибализация и риск фильтра за масштабированный контент на новом домене.
